# Procediment de treball

## Tasques i branques

- Les issues de treball les crea l'alumnat amb els formularis de la plantilla; no espereu una llista tancada preparada pel professorat.
- Creeu una issue amb responsable, resultat, dependències i evidència.
- Useu una branca com `23-model-dades` o `41-prova-accessibilitat`.
- Feu commits breus que expliquen el resultat, no només l'acció.
- Relacioneu la pull request amb la issue (`Closes #23`).

## Revisió

Una altra persona revisarà la pull request. Abans d'incorporar-la, cal comprovar:

- correspondència amb la necessitat o tasca;
- coherència amb documents anteriors;
- proves o comprovacions aplicables;
- autoria, fonts i ús d'IA;
- absència de credencials i dades personals reals.

## Definició de Fet

Un treball està fet quan el resultat és accessible, revisat, provat quan correspon, documentat i enllaçat des de la issue. Un canvi de codi sense prova o un document sense revisió continua en curs.

## Versions

Useu etiquetes immutables: `dossier-0-v1.0`, `dossier-1-v1.0`, `dossier-2-v1.0`, `pla-v1.0`, `iteracio-1-v0.1`, `prototip-v1.0` i `tancament-v1.0`. Si cal corregir una entrega, publiqueu `v1.1`; no mogueu l'etiqueta anterior.

## Traspàs

L'emissor tanca una versió i una acta en `traspassos/`. El receptor audita, consulta i accepta abans d'assumir la custòdia. No esborreu ni reatribuïu decisions anteriors.
